# 144. A link opened in Cartouche fills in the code of Cartouche Cloud and asks before it links

2026-11-21

The link `cartouche://cloud/link?code=…`, which the site's **Open in Cartouche** button and QR code give, opens **System › Cartouche Cloud** with the code filled in, and links nothing by itself ([`CartoucheCloudLink.swift`](../../launcher/Sources/CartoucheCloudLink.swift), `opened`). The page asks first, in an alert, with the code it was given: **Link this iPhone to a Cartouche Cloud account?**, which says to link only from a link the player opened themselves, from their account's page on build.cartouche.cloud, and, for an iPhone linked already, that linking takes the place of its account ([`CartoucheCloudPage.swift`](../../launcher/Sources/CartoucheCloudPage.swift)). **Link** links as a code typed on the page does; **Cancel** forgets the code. A code typed on the page still links with its own **Link**, the player having typed it.

This amends [decision 136](136.md), where the link linked the iPhone at once.

**Why.** Anyone can make that link, with the code of their own account, and put it on a web page, in a message or in a QR code: opened on the player's iPhone, it linked the iPhone to that account at once, in place of the player's own if it had one, and the library then offered that account's games to install, from the copies its owner sent. An automated security review flagged it on 21 November 2026 as a login CSRF. The platform tells nothing of an account before its code is used, so the question cannot name the account; it says where a good link comes from instead, and costs the player one tap on a link they did open.
