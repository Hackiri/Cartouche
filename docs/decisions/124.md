# 124. An app that is not a game may ask StikDebug for JIT

2026-11-13

An app that is not a game may need JIT, which its App settings say (**Needs JIT**, LiveContainer's own setting of the app), with the app's JIT script when StikDebug asks one, a file kept base64 as LiveContainer keeps it ([`CartoucheAppSettingsView.swift`](../../launcher/Sources/CartoucheAppSettingsView.swift)). Cartouche then asks StikDebug for JIT as the app opens, as LiveContainer's Apps tab does with StikDebug for its JIT enabler (`LCUtils.askForJIT`): the `stikjit://enable-jit` link with Cartouche's identifier and the script ([`CartoucheGameActions.swift`](../../launcher/Sources/CartoucheGameActions.swift), `jitLaunch`). StikDebug, an app of its own, starts Cartouche again under its debugger, and LiveContainer opens the app it selected; such an app opens in Cartouche's place, never behind the console. A player who comes back to Cartouche first is asked whether to open the app without JIT; without StikDebug on the iPhone, the start says to install it, from stikdebug.xyz. Games never ask for JIT: 5 holds for them. Amends 5.

**Why.** The player asked for JIT for the apps of 123 (2026-11-13). What works on iOS 26 and 27, which the supported iPhones run: Apple's debugger alone no longer gives an app JIT, StikDebug does, with a script for the app on an A15 or later, every supported iPhone; StikDebug picks its own scripts by the app's name, which inside Cartouche is Cartouche's, so the app's script comes from its settings, as LiveContainer's docs ask for an app inside LiveContainer. Not SideStore's JIT: it reaches no app on iOS 26, LiveContainer's docs leave the built-in SideStore out, and SideStore's deep links have no JIT route. Not StikJIT's in-app JIT with iOS 27's in-app pairing: it needs LiveContainer's helper process, which the pinned LiveContainer 3.8.11 has not. StikDebug needs what Cartouche's setup already has, LocalDevVPN and the pairing file, which Cartouche's folder in Files holds.
