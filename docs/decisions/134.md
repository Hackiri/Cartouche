# 134. The System page opens LiveContainer's and SideStore's own pages

2026-11-12

The System page opens the own pages of the apps Cartouche is built on, under **LiveContainer and SideStore**: **Open LiveContainer** shows LiveContainer's Apps and Settings pages in a sheet over the System page (`CartoucheLiveContainerView.swift`, removed by 135), and **Open SideStore** starts the built-in SideStore in Cartouche's place, as LiveContainer+SideStore's own **Open SideStore** does (`LCUtils.openSideStore`), the ⎋ button LiveContainer adds to SideStore's My Apps page coming back to Cartouche; not while a game is paused behind the console or an install is under way, and once the copies of saves under way are done. Narrows 24: Cartouche still drives both by itself and opens neither on its own; the tab bar, the page in the Settings app, the share sheet extension and the links to LiveContainer's pages stay gone. An IPA that is not a game, which Import installs all the same, now says it is in LiveContainer, from the System page. **Open SideStore** waits for the pairing file and LocalDevVPN, and SideStore's launch asks for a pairing file only when none is in place ([patch 0024](../../app/patches/sidestore/0024-ask-for-a-pairing-file-only-when-none-is-in-place.patch)): when the iPhone did not answer, LocalDevVPN being off, minimuxer laid it on the pairing file, the very one Cartouche had put in place, and the player would rather have Cartouche's setup be where the file is put and replaced (2026-11-12). SideStore also starts minimuxer again before an operation when its start at launch did not go through ([patch 0025](../../app/patches/sidestore/0025-start-minimuxer-again-for-an-operation-when-its-start-at-launch-failed.patch)): installs in its pages stopped at *No valid pairing file has been loaded* until it was opened again. And Cartouche's pairing file is the one SideStore reads: the copies SideStore saves when a file is imported on its own pages (`PairingFile_RemoteRP.plist`, `PairingFile_Lockdown.plist`), which it reads before Cartouche's, go as Cartouche puts its file in place and each time it comes to the front (`CartouchePairing.claim`): a file picked at the Pairing File Required prompt of an older build was a stale pairing, and every install failed with *Handshake failed: RemotePairing(PairVerifyFailed)*.

**Why.** The player asked to manage LiveContainer and SideStore from Cartouche, or to open both apps from it (2026-11-12): an app that is not a game, installed from Import or wanted from an IPA, had no page to start from since 0006 took LiveContainer's Apps tab away, and SideStore's own pages, its sources, apps and settings, were out of reach. Opening their own pages, as LiveContainer+SideStore itself does, gives every option of theirs at once, where screens of Cartouche's own for each would be a second copy of both apps to keep up. Reversed by 135 for the launchers, the same day: SideStore's pages met its pairing prompts and device checks, which Cartouche's own flows never need.
